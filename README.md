## 2. Implementation Summary

### 2.1 GitHub Actions Workflows Created

#### **Workflow 1: ZAP Baseline Scan** (`zap-baseline.yml`)

- **Trigger:** Push and Pull Request to main branch
- **Frequency:** On every commit
- **Duration:** ~5 minutes
- **Scan Type:** Quick baseline security check

**Key Steps:**

1. Checkout code
2. Setup JDK 17 (Temurin distribution)
3. Build application with Maven
4. Build Docker image
5. Run application in container
6. Execute ZAP baseline scan
7. Upload report artifact
8. Cleanup Docker containers

#### **Workflow 2: ZAP Full Scan** (`zap-full-scan.yml`)

- **Trigger:** Weekly schedule (Sunday 2 AM) + Manual dispatch
- **Frequency:** Scheduled + On-demand
- **Duration:** ~20-30 minutes
- **Scan Type:** Comprehensive security analysis

**Key Steps:**

1. Same as baseline workflow
2. Execute full ZAP scan with extended timeout
3. Generate detailed HTML report
4. Archive artifacts for 90 days

### 2.2 Configuration Files

#### **ZAP Rules Configuration** (`.zap/rules.tsv`)

- Configured scanning rules for 30+ security checks
- Set thresholds for each rule (OFF, LOW, MEDIUM, HIGH)
- Action levels (IGNORE, WARN, FAIL)
- Coverage includes:
  - Anti-CSRF tokens
  - Security headers (X-Frame-Options, CSP, HSTS, etc.)
  - Information disclosure
  - SQL injection detection
  - XSS detection
  - Cookie security
  - SSL/TLS configuration

### 3.1 Initial ZAP Scan Results

### 3.2 Medium Severity Vulnerabilities (Fixed)

#### **1. Content Security Policy (CSP) Header Not Set**

- **Risk:** XSS and data injection attacks
- **Fix:** Added comprehensive CSP header
- **Policy:**
  ```
  default-src 'self'
  script-src 'self' 'unsafe-inline' 'unsafe-eval'
  style-src 'self' 'unsafe-inline'
  img-src 'self' data: https:
  font-src 'self' data:
  connect-src 'self'
  frame-ancestors 'none'
  base-uri 'self'
  form-action 'self'
  ```

#### **2. Missing Anti-clickjacking Header**

- **Risk:** Clickjacking attacks
- **Fix:** Added `X-Frame-Options: DENY` header
- **Impact:** Prevents framing of application in malicious sites

### 3.3 Low Severity Vulnerabilities (Fixed)

#### **3. Insufficient Site Isolation Against Spectre**

- **Risk:** Side-channel attacks
- **Fixes:**
  - `Cross-Origin-Resource-Policy: same-origin`
  - `Cross-Origin-Embedder-Policy: require-corp`
  - `Cross-Origin-Opener-Policy: same-origin`

#### **4. Permissions Policy Header Not Set**

- **Risk:** Unauthorized browser feature access
- **Fix:** Added restrictive Permissions-Policy header
- **Restricted Features:** Camera, microphone, geolocation, magnetometer, gyroscope, accelerometer

#### **5. X-Content-Type-Options Header Missing**

- **Risk:** MIME sniffing attacks
- **Fix:** Added `X-Content-Type-Options: nosniff` header

### 3.4 Informational Alerts (Browser-Generated)

- Sec-Fetch-Dest header missing (4 instances)
- Sec-Fetch-Mode header missing (4 instances)
- Sec-Fetch-Site header missing (4 instances)
- Sec-Fetch-User header missing (4 instances)
- Storable and cacheable content (5 instances)
- User Agent Fuzzer (36 instances)

**Note:** These are informational and generated by browsers. Not backend code issues.

| ---------------------------- | ---------------- | ---------------------------- |
| X-Frame-Options              | DENY             | Clickjacking prevention      |

## 9. Lessons Learned

### 9.1 DAST vs SAST

- **SAST (SonarCloud):** Finds code-level vulnerabilities
- **DAST (OWASP ZAP):** Finds runtime/configuration vulnerabilities
- **Complementary:** Both needed for comprehensive security

### 9.2 Security Headers Importance

- Security headers prevent common attack vectors
- CSP policy requires careful configuration to avoid breaking functionality
- Spectre mitigation headers are newer but important for modern security

### 9.3 CI/CD Security Integration

- Automated security scanning catches issues early
- Regular baseline scans provide quick feedback
- Full scans provide comprehensive coverage (scheduled)
- Artifact retention important for audit trails
